9. 数据边界与备注

  • 测试范围：5 长度组 × 并发阶梯 × k=3/4/5 = 87 random 档 + 9 Agent session（3 session × 12 轮 / k），全部成功零失败；逐 k 独立 boot。
  • 每 k 的 1K c1 首档冷启动保护：连跑两遍同名标签，取热身值，冷启动首跑静默剔除。
  • k=4 在 util 0.92 / capture 768 下于 1K c128 峰值 CUDA OOM（余量 217MB 需 276MB），c128 带失败后引擎退出；util 0.90 + capture 640 配置下全 29 档 + Agent 零失败（失败现场存 matrix_k4_failed_v1.log）。
  • k=3 Agent 档数据采集于修正 agent_tools_sim.py 的 URL 传参错误（初轮全 404）之后；k=5 Agent 为修正后首轮数据。
  • 单请求档（c1）接受率受随机数据影响方差大（如 4K c1 k=5 acc_len 1.07 → 49.6 tok/s），属数据彩票非系统异常；聚合档与多请求档稳定。
  • 接受率随上下文变长显著上升：1K acc_len ~1.9-2.3，64K 达 3.4-5.1（k=5 接近上限 6）——长上下文长生成是 DSpark 收益最大场景。
  • 84G 卡 KV 池 13.47M token（util 0.92）/ ~12.8M（util 0.90）；最大档 64K/64K c8 = 8×128K = 1.05M token，KV 占用 ~8%。
  • 原始数据：.158 /root/test_ops/matrix_k3.log / matrix_k4.log / matrix_k5.log（头部含完整启动命令 BOOT CMD）+ matrix_boot_k*.log + matrix_k*_agent_s*.out + matrix_k4_failed_v1.log。
