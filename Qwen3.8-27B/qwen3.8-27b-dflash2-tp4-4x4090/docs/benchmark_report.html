2. 部署环境与服务配置

项目配置
硬件8×RTX 4090 48G 服务器，本次使用 GPU 4/5/6/7（TP=4；GPU 3 另有其他进程占用，未参与）
运行方式docker 容器 vllm/vllm-openai:nightly（vLLM 0.26.1rc1.dev1177+ga9a17e709）
模型Qwen/Qwen3.8-27B-FP8，served name Qwen3.8-27B；权重走 Marlin kernel（SM8.9 无原生 FP8）
投机解码--speculative-config {"method":"dflash","model":"incoai/Qwen3.8-27B-DFlash2","num_speculative_tokens":3}
KV cache约 152 万 tokens（256K 满长请求并发上限约 5.8 路）
API端口 8124（OpenAI 兼容接口），max_model_len=262144

启动命令（docker）

docker run --name qwen27b-dflash \
  --gpus '"device=4,5,6,7"' \
  --ipc=host \
  -p 8124:8000 \
  -v /mnt/nvme1/.cache/huggingface:/root/.cache/huggingface/hub \
  vllm/vllm-openai:nightly \
  Qwen/Qwen3.8-27B-FP8 \
  --served-model-name Qwen3.8-27B \
  --trust-remote-code \
  --tensor-parallel-size 4 \
  --dtype auto \
  --max-model-len 262144 \
  --max-num-seqs 512 \
  --gpu-memory-utilization 0.95 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder \
  --reasoning-parser qwen3 \
  --mm-encoder-tp-mode data \
  --speculative-config '{"method":"dflash","model":"incoai/Qwen3.8-27B-DFlash2","num_speculative_tokens":3}' \
  --api-key <内网约定>

3. 测试方法

项目口径
工具vllm bench serve（vLLM 官方，openai-chat 后端，endpoint /v1/chat/completions）
数据集 / 并发random（固定输入/输出 token 数）× burst 并发（请求数=并发数）
输出长度--ignore-eos，每请求输出精确到目标值（1024/4096/8192/32768）
输入 tokens表中为实测值（chat 模板占用导致略低于目标）
指标口径全部取自工具输出 JSON 官方字段；除 TTFT 由 ms 换算为 s（÷1000）外，其余数值均为官方原值

4. 测试数据（4 组 21 档，按输入/输出组合分表）

TTFT 各列已由官方输出的 ms 换算为 秒 s（÷1000）；Mean TPOT 保持官方 ms 原单位。总/均 = 全部请求合计 / 每请求平均（实测值）。

4.0 指标含义

列含义
并发该档 burst 同时发出的请求数（等于该档总请求数，全部同时开跑）
成功 / 失败该档完成 / 失败的请求数（官方字段 completed/failed）
输入 tokens 总/均全部请求实际输入（prompt）token 合计 / 每请求平均——实测值
输出 tokens 总/均全部请求实际输出 token 合计 / 每请求平均；ignore_eos 下精确等于目标值
Duration s该档整段测试耗时：从第一个请求发出到最后一个请求完成（官方字段 duration）
Request throughput (req/s)成功请求数 ÷ Duration，每秒完成的请求数
Output tok/s输出 tokens 总量 ÷ Duration，整机每秒产出的生成 token 数（官方字段 output_throughput）
Mean TTFT (s)首 token 延迟平均值：从发出请求到收到第 1 个生成 token 的耗时
P50 / P95 TTFT (s)首 token 延迟的 50 / 95 分位
Mean TPOT (ms)首 token 之后平均每个输出 token 的耗时；单流速度 ≈ 1000 ÷ TPOT
DFlash2 接受率 %投机解码 draft token 被主模型接受的比例
DFlash2 接受长每轮投机平均被接受的 token 数（含 1 个真 token；num_spec=3 上限 4.0）

5. 数据边界与备注

  • 测试范围：1K→1K、4K→4K、8K→8K、4K→32K 四组 × 并发 1/2/4/16/32（1K 组加测 64）；8K→32K 组未测。
  • 运行环境为 docker 容器（nightly 镜像）；容器内 GPU 重新编号 0-3。
  • 权重走 Marlin kernel（SM8.9 无原生 FP8 计算，weight-only 路径），属该平台正常日志与行为。
  • 测试数据为 random 数据集随机 token；并发为 burst 全同时发出，不含错峰/限速场景。
  • 原始数据：被测机本地 /root/qwen27b-bench/results-dflash/（21 个 JSON + 逐档 log）。
