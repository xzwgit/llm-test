1×GB10 · Qwen3.8-27B（FP8）· vLLM DFlash2 压测报告（v2）

1. 概述

被测配置：DGX Spark（单机单卡 GB10，121GB 统一内存）· vLLM nightly 0.28.1rc1.dev283+g300f68832 · 主模型 Qwen/Qwen3.8-27B-FP8（Cutlass FP8，KV bf16）· 投机解码 DFlash2 num_speculative_tokens=7（draft：incoai/Qwen3.8-27B-DFlash2）· chunked prefill 32768 · 256K 上下文
  • 测试范围：随机 token 九档、Agent 任务流 12 轮、真实文本单流 5 组、prefix cache 验证 3 次、多轮对话 5 轮、热态长输出 3 组。
  • 随机 token 标准口径（vllm bench serve，官方工具）：单请求 decode 15.5 ~ 20.9 tok/s（TPOT 47.3~64.0 ms）；并发 4 聚合 43.5 ~ 44.7 tok/s（1K/4K），8K×c4 36.6。
  • Agent 工具调用场景：decode 40.0 ~ 47.5 tok/s（结构化输出投机加速明显），TTFT 0.24~1.13 s 且逐轮抬升。
  • TTFT 显著受投机调度挤压：冷态 8K 输入 2.86 s（单流）、8K×c4 达 22.66 s；长输入冷 prefill 慢（20.5K token 首次 15.0~22.4 s）。
  • prefix cache 延迟一轮命中：相同 13.8K 前缀连续三次请求，TTFT 15.0 s → 14.98 s（未命中）→ 0.78 s（第三次才命中）；多轮对话同样表现为前两轮冷、第三轮起命中（1.1 s 量级）。

6. Prefix Cache 行为（本测试重点观察项）

方法：同一 13,860 token 长前缀请求连续发送 3 次（max_tokens=1，总时长近似 TTFT）。

次序输入 tokens总时长 ≈ TTFT (s)判定
第 1 次13,86015.02冷 prefill
第 2 次13,86014.98未命中（仍完整重算 prefill）
第 3 次13,8600.78命中
  • 缓存命中存在一轮延迟：相同前缀的第二次请求并未命中（Mamba 混合架构的状态缓存写入/生效时机晚于请求间隔）；第三次起命中，TTFT 0.78 s。
  • 多轮对话（8K 文档 system，逐轮追加）同样表现：第 1/2 轮 TTFT 22.35/22.74 s（冷），第 3~5 轮 1.07~1.13 s（命中）。
  • 热态同前缀长输出（输出 1,024 × 3 问）：TTFT 0.82~1.00 s，decode 13.0~15.0 tok/s，总吞吐（输入+输出）÷ 总耗时口径 270~311 tok/s。
  • 冷 prefill 20.5K token 需 15.0~22.4 s——投机解码开启后 prefill token 预算被压缩（batched 32768 未完全兑现），是长输入场景 TTFT 的主要短板。

7. 结论

  • 单流 decode：随机口径 15.5~20.9 tok/s；真实文本 11.9~16.5 tok/s；Agent 工具调用 40.0~47.5 tok/s（单流最高观测值 47.5）。
  • 聚合吞吐：并发 4 时 1K/4K 档 43.5/44.7 tok/s，8K 档 36.6 tok/s。
  • TTFT 是主要短板：投机调度压缩 prefill 预算，8K×c4 达 22.66 s、冷 20.5K prefill 15~22 s；多轮 Agent 场景 TTFT 逐轮抬升。
  • prefix cache 延迟一轮生效：同前缀第 2 次请求仍完整重算，第 3 次起命中；对"每个新对话首两轮"的体验影响直接。
  • 结构化输出（工具调用 JSON）投机加速明显（约 3 倍于自然语言轮）。

8. 数据边界与备注

  • 测试范围：九档随机 token + Agent 12 轮 + 真实文本 5 组 + 缓存验证 3 次 + 多轮 5 轮 + 热态长输出 3 组。长输出（32K）组、8 以上并发未测试。
  • 主模型为 FP8 包（KV bf16），与 NVFP4 包的 KV 精度不同；投机解码参数 num_speculative_tokens=7 全程生效。
  • 接受率：vLLM 服务日志无逐周期接受率输出，本报告以工具轮/自然语言轮的速度差表征投机效果。
