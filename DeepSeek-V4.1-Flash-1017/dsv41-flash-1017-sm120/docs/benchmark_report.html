6. 相位论文场景组（flip 先导 + needle 检索，1017 权重）

测试结果
flip 先导（flipping-completion 相位探针）P("8")/P("32") 未进入 top-20（顶选 W/V），未观测到周期-2 振荡（flips=0 / 0 有效长度）
needle 检索（256 条，8 residue × 32，129K 上下文）255/256 = 99.6%，各 residue 31~32/32 曲线平坦；even/odd gap = −0.008 ≈ 0（论文签名 even>odd 未复现）；唯一失败 (r=2, j=0) 为空输出，非相位相关
单条用时2.9 s/prompt（129K prefill + 48 token 输出）

本组结果为 1017 更新版权重上的测量；flip/needle 标定基于原版权重的相位行为，1017 未见现象本身即是本测试的有效结果。

7. NVFP4 KV 探针（--kv-cache-dtype nvfp4_ds_mla）

项结果
boot 探针worker 初始化即拒：ValueError: nvfp4_ds_mla needs the V4.1 KV records, which FlashMLA decodes only on SM100.
代码侧FLASHINFER_MLA_SPARSE_DSV41 的 supported_kv_cache_dtypes = [auto, bfloat16, fp8, fp8_e4m3, fp8_ds_mla]

结论：DSV4.1（1017）的 NVFP4 KV 在 SM120 上为架构性不可用（FlashMLA 的 V4.1 KV records 解码仅实现于 SM100）；该路径与本机无关，本报告 KV 口径为 fp8。

11. 数据边界与备注

  • 测试范围：文本 random 压测 25 档 + 相位场景组 + NVFP4 探针 + completions 正确性；全档零失败，单次 boot 全程未重启（boot 后 323 验证通过）。
  • 投机配置 DSpark spec=3（1017 的收敛配置；同系列 10-10 报告为原版权重 spec=5，两份报告口径独立、不作对比）。
  • capture 512 为本机显存适配（capture 1024 在本栈 CUDA graph 画像段 OOM，实测后下调；配合 expandable_segments）。
  • Agent 场景（真 tools 调用，12 轮）与 DSpark 投机的隔离结论：① 1017 + 无投机（vLLM 0.32.0）：Agent 12/12 轮、0 错误、结构化 tool_calls 全部成功（get_gpu_alert/query_metrics/scale_node），平均 2.93 s/轮，chat 正确性完美（reasoning 与 content 正确分离，17×19=323）。② 1017 + DSpark 投机（k=3/4/5/7，vLLM 0.32.0 与 nightly 均验证）：chat/思考格式输出损坏（思考流乱语循环、无结构化 tool_calls），损坏形态与 k 值和 vLLM/torch/FlashInfer 版本无关。③ 已知对照：原版权重 + DSpark k=3 同款配置的 Agent 记录为 26~32 次工具调用零错误。结论：DSpark 投机解码与 DeepSeek-V4.1-Flash-1017 检查点在思考/chat 格式上不兼容（当前 vLLM），k=3/4/5/7 Agent A/B 因全部损坏而无从比较；纯文本 /v1/completions 路径不受影响（本报告 25 档与相位场景组均为投机开启下的有效数据）。生产建议：1017 提供 chat/Agent 服务时关闭投机解码，或等待上游修复。
  • 视觉档未测（--language-model-only 纯文本启动）；mm 档不适用。
  • 原始数据：被测机 /root/vllm32/ops/v41_1017_full.log（25 档官方输出全量）+ v41_1017_boot.log（服务端日志）；相位场景组 /root/phase_test/results_1017/。
