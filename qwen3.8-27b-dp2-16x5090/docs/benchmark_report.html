双机 16×RTX 5090 Qwen3.8-27B DP2 压测报告

基于 vLLM 官方基准工具 vllm bench serve 的输入/输出 token 组合 × 并发梯度测试（26 档）。指标名称、单位与工具官方输出保持一致，未做二次换算。附跨机 NCCL/GDR 验证专节。

报告日期：2026-09-01 硬件：server1 + server2 ，各 8×RTX 5090 32G（共 16 卡） 部署：TP=8/机 + DP=2（bf16，MTP×3） vLLM 0.28.0 测试窗口：16:24–17:58

3. 跨机 NCCL / GPUDirect RDMA 验证

验证项结果证据
跨机 NCCL 通信器（12 rank）✓ 生效TP=12 尝试日志：ncclCommInitRank 12 rank Init COMPLETE，耗时 0.49s（server1 + server2 全部 rank）
跨机通道走 GPUDirect RDMA✓ GDRDMA日志原文：Channel 00/0 : 4[4] -> 8[0] [send] via NET/IB/2/GDRDMA（rank7→rank8 跨节点，双轨均有）；机内通道 via P2P/CUMEM
NCCL 集合通信基准（16 卡）✓ 41 GB/snccl-tests（本集群既有实测）：all_reduce 双轨 41.0 / 单轨 24.1 GB/s、all_gather 40.9、alltoall 7.5 GB/s busbw
跨机 TP 可行性（本模型）✗ 不可行TP=16：注意力头 24 不整除；TP=12：头整除但词表维度不整除（vocab_parallel_embedding 断言失败）→ Qwen3.8-27B 在 16 卡上无合法跨机 TP 组合
本部署 DP=2 跨机通信无集合通信DP=2 每台独立 TP=8（机内 PCIe P2P），跨机仅 DP 调度 RPC（管理网）+ 权重分发，无跨机 NCCL 集合流量

结论：跨机 NCCL/GDR 链路本身完全可用（通信器建立、GDRDMA 通道、41 GB/s 集合带宽均验证通过）；生产选 DP=2 是因 Qwen3.8-27B 结构限制无法跨机切分 TP，而非网络问题。

6. 关键观察

  • 吞吐上限：整机输出吞吐 1K×64 峰值 4,005 tok/s；32K 长输出组并发 32 仍 1,727–1,800 tok/s。同档对比 4×4090 TP4 模板（峰值 1,288 / 长输出 936–1,057）约 1.8–3.1×，符合双机 16 卡预期。
  • 单流 decode：4K→4K 单流最高 118.07 tok/s（TPOT 8.38ms）；输出拉长到 32K 后单流 79.8–85.4 tok/s（TPOT 11.7–12.5ms），KV 增长衰减幅度明显小于 4090 基线（67 tok/s / 29.7ms）。
  • TTFT：低并发 ≤4 时全部 <1s；最大 P95 10.34s（8K×32K×c32），8K 输入 c32 P95 8.73s，均大幅优于 4090 基线（43.58s）——prefill 侧双机分摊效果显著。
  • MTP 接受率：随机文本 18.6–82.5%，随输出长度/并发升高而上升（长链自相关性强）；1k1k-c1 的 18.6% 为单请求短链低样本点。
  • DP 负载均衡：压测全程两台 GPU 利用率 ≥95%，请求由 DP 协调器自动分发，无单边热点。

7. 数据边界与备注

  • 测试数据为 random 数据集随机 token，MTP 接受率与真实业务文本存在差异；吞吐/TTFT 口径不受影响。
  • 并发为 burst 全同时发出（request_rate=inf），不含错峰/限速场景。
  • Qwen3.8-27B 为混合线性注意力架构（linear_attention + full_attention 间隔 4），跨机 TP 需同时整除头数与词表维度，16 卡集群无合法组合；如需跨机 TP 压测建议换 128 头模型（如 DeepSeek 系）。
  • 原始数据（逐档 JSON + log）: server1 /root/qwen27b-bench/results/（26 JSON + runner.log）。
  • 环境备注：GDR 依赖 libcuda 字节补丁（RTX 5090 GeForce 解锁）+ NVreg P2P 参数，详见 harbor /root/5090gdr/ 文档体系。
