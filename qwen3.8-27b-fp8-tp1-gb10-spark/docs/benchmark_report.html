Qwen3.8-27B-FP8（官方包）DGX Spark（GB10）单机 TP1 压测报告

基于 vLLM 官方基准工具 vllm bench serve 的部分矩阵测试。指标名称、单位与工具官方输出保持一致。

报告日期：2026-09-03 硬件：DGX Spark（GB10，SM121，121G 统一内存） 模型：Qwen3.8-27B-FP8（TP=1，MTP=3） vLLM nightly 0.28.1rc1.dev283 范围：3 组 9 档（部分矩阵）

1. 测试结论

测试档位
9/9 全部成功

3 组输入/输出组合 × 并发 1/2/4，零失败

单流 decode
14–17 tok/s

TPOT 58–78 ms

并发 4 聚合吞吐
47.1–52.0 tok/s

1K/4K/8K 组并发 4 档

MTP 接受率
45.4–76.8%

接受长度 2.36–3.30

  • 关键发现：该官方 FP8 checkpoint 的 KV cache 为 bf16（未量化）——启动日志 kv_cache_dtype=auto，KV 容量 1,014,183 tokens（256K 满长并发约 3.87 路）。decode 每 step 读全部 KV，bf16 的读取数据量是量化 KV 的 2 倍，带宽密集的 decode 直接受累（TPOT 58–78 ms）。
  • GEMM 走 CutlassFp8BlockScaled kernel（非 Marlin/FlashInferFP8），且平台提示 "Not enough SMs to use max_autotune_gemm"——SM121 上该 kernel 效率一般。
  • 外部参考：MiaAI-Lab issue #186 所说 "fp8 fits very well" 指其 DeepSeek 栈（dspark 用 nvfp4_ds_mla 量化 KV），不能外推到 Qwen 官方 FP8 包（其 KV 为 bf16）。

2. 部署环境与服务配置

项目配置
硬件DGX Spark（NVIDIA GB10，SM121，121G 统一内存；nvidia-smi 不报显存数字，以下为启动日志口径）
权重加载29.28 GiB（本地路径 ~/Qwen3.8-27B-FP8，含 MTP 头），比 NVFP4 包大 ~6.8 GiB
KV cachebf16（未量化），容量 1,014,183 tokens（256K 满长并发上限约 3.87 路）
kernel 路径CutlassFp8BlockScaledMMKernel（FP8 GEMM）+ FlashAttention（attention 后端）
推理框架vLLM 0.28.1rc1.dev283+g300f68832（nightly，venv ~/vllm，Rust frontend）
API端口 8123（OpenAI 兼容接口），max_model_len=262144
启动备注autotune 秒级完成（无 CuteDSL 慢调优问题）；VLLM_ENGINE_READY_TIMEOUT_S=3600 为保险项非必需

启动命令

export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_DISABLE_XET=1
export VLLM_WORKER_MULTIPROC_METHOD=spawn
export CUDA_VISIBLE_DEVICES=0
export VLLM_USE_RUST_FRONTEND=1

vllm serve /home/nvidia/Qwen3.8-27B-FP8 \
  --served-model-name Qwen3.8-27B \
  --trust-remote-code \
  --tensor-parallel-size 1 \
  --host 0.0.0.0 --port 8123 \
  --gpu-memory-utilization 0.95 \
  --max-model-len 262144 \
  --max-num-batched-tokens 32768 \
  --enable-chunked-prefill \
  --async-scheduling \
  --enable-prefix-caching \
  --speculative-config '{"method":"mtp","num_speculative_tokens":3}' \
  --load-format fastsafetensors \
  --reasoning-parser qwen3 \
  --tool-call-parser qwen3_coder \
  --enable-auto-tool-choice \
  --api-key <内网约定>

5. 数据边界与备注

  • 测试范围：仅 1K→1K、4K→4K、8K→8K × 并发 1/2/4（部分矩阵）；4K→32K、8K→32K 及 16/32/64 高并发档未测。
  • KV cache bf16 为该官方 FP8 checkpoint 自带行为（非启动参数指定）；如需 KV 量化需显式传 --kv-cache-dtype fp8（未在本轮测试）。
  • 权重以本地目录方式加载（~/Qwen3.8-27B-FP8 平铺结构）。
  • prefix caching 虽开启但被 MTP+Mamba 架构自动禁用。
  • 结论适用范围：SM121（GB10）+ vLLM nightly 0.28.1rc1；不代表原生 FP8 硬件（B200/GB300 等）上的表现。
  • 原始数据：压测机本地 /root/qwen27b-bench/results-spark44-fp8/（9 个 JSON + 逐档 log）。
